Local-first is a boundary, not a magic shield

ai DeMemory keeps its own storage and retrieval local by default, enforces bounded capabilities, and gates durable writes. Your host agent and chosen sync tools still have their own trust boundaries.

What the design protects

The primary security goals are to keep personal memory out of the public distribution repository, constrain which local data a client can retrieve, preserve provenance, and prevent unreviewed content from silently becoming durable truth.

This page describes the current public source. Stable 2.0.0 has the local vault, MCP, review, and secret-scanning foundation; the wizard, resource profiles, server-enforced profile upgrades, and idle leases are unreleased 2.1.0rc1 controls.

  • The vault root is explicit and separate from the source repository.
  • MCP capability profiles are enforced by the server, not only advertised to the client.
  • Markdown is canonical; generated SQLite indexes are replaceable.
  • Secret-like content blocks durable promotion and generated report writes.
  • Review fingerprints bind an approval to the exact plan that was inspected.
  • Resource and process ceilings reduce accidental runaway work.

Know every trust boundary

System actors and responsibilities
Actor Can see or change Boundary
ai DeMemory The explicitly bound vault and generated local artifacts Root checks, profiles, budgets, review rules
Host agent Context returned to its process; proposals when allowed The host's provider, permissions, logging, and token policy
Sync or backup Whatever vault files you choose to synchronize Your repository visibility, encryption, and access controls
Public repository Source, docs, package metadata, public fixtures Must never be used as a personal vault

“Local” does not mean recalled text can never leave the machine. If a cloud-backed host agent receives that text, its provider may process it under the host's configuration and terms.

Default data flow

  1. You create and bind a private local vault.
  2. The Python runtime indexes reviewed Markdown into local SQLite FTS.
  3. A local client asks for bounded context through stdio MCP or the loopback API.
  4. The server filters the request through root, tool-profile, visibility, and budget rules.
  5. Only the selected context returns to the requesting host.
  6. Any durable candidate waits in a reviewable inbox until explicitly approved.

The runtime makes zero model and embedding calls in the current profiles. Optional provider imports, hook metadata, scheduler jobs, backups, and sync are separate opt-in actions.

This documentation site has no analytics, cookies, external fonts, client-side search, or automatic external requests. Following a GitHub link is an intentional network navigation.

Controls that carry authority

Capability and root enforcement

Generated MCP configuration names the exact vault, selects a server-enforced profile, and requires a bound root. The public-repository profile is narrower than the private-vault core profile.

Review and provenance

Retrieved items include source, status, confidence, and path. Durable changes require a reviewer and exact preview fingerprint; pinned values are not automatically overwritten.

Secrets and sensitive content

Secret scanning blocks sensitive-looking content from versioned durable memory and generated reports. Treat this as defense in depth: review every candidate and never use memory as a credential store.

Local transports

Prefer stdio MCP. The optional REST API defaults to loopback. Set an API key before any non-loopback bind; remote HTTP and OAuth are outside the current release design.

Process and resource containment

Profiles cap input, scanning, output, context, and background work. MCP idle leases terminate abandoned servers, while owned external process trees are reaped on timeout or shutdown.

Current limitations

  • Secret detection can have false positives and false negatives; it does not replace human review.
  • Plaintext Markdown inherits operating-system, disk, editor, backup, and sync protections.
  • A compromised host with access to your account may read any vault files that account can read.
  • The package cannot clean up unrelated processes created by Codex, a browser, a plugin, or another host.
  • Non-loopback REST exposure needs a separate authentication and privacy design beyond the local default.
  • Vector search remains future work and is not part of the current security foundation.

For the smallest operating surface, select minimal with model policy off, keep recall manual, and do not install hooks or scheduled jobs.

Report a vulnerability privately

The repository now has an approved SECURITY.md policy covering supported versions, trust boundaries, reportable findings, limitations, and disclosure handling.

Use GitHub Private Vulnerability Reporting for suspected vulnerabilities. Do not open a public issue, discussion, or pull request for an undisclosed vulnerability, and use synthetic evidence instead of real credentials or private-memory content.
