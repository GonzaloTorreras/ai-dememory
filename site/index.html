A reviewed memory lifecycle

Agents can retrieve trusted context and prepare candidates. Durable Markdown still crosses an explicit review boundary.

  1. 01

    Capture

    A host or import proposes a bounded memory candidate.

  2. 02

    Review

    Check provenance, sensitivity, conflicts, and lasting value.

    Human approval boundary

  3. 03

    Remember

    Approved knowledge becomes readable, portable Markdown.

  4. 04

    Consolidate

    Reviewable maintenance finds duplicates and stale material.

Three places, three responsibilities

This separation keeps public code auditable and personal memory private.

Public source

Repository

Code, package metadata, documentation, and public fixtures. Never your personal memory.

Isolated runtime

Installed tool

The Python CLI and MCP server, normally installed with pipx or uv.

Private data

Your vault

Canonical Markdown and disposable indexes under a separately chosen root.

Package installation is passive: it does not scan chat histories, install hooks or jobs, or create durable memories. 

pipx install ai-dememory==2.1.0
ai-dememory init ~/code/my-memory --wizard --require-version 2.1.0

This is the published 2.1.0 route. Its historical version gate belongs only to the stable wizard flow; connecting an AI client, imports, hooks, and schedules remain separate choices.
