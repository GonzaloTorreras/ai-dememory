The system boundary

The public repository distributes code and fixtures. An isolated installed tool operates against one explicitly bound private vault. No generated index is authoritative.

Release lens: canonical Markdown, local MCP, setup planning, and client configuration exist in stable 2.0.0. Server-enforced resource profiles, the wizard, and generated idle leases below describe the unreleased 2.1.0rc1 source line.

  1. AI client: Codex, Claude, or another local MCP-capable host requests context.
  2. Delivery boundary: local stdio MCP is preferred; loopback REST exists for local scripts and dashboards.
  3. Python policy engine: validates roots, capabilities, inputs, budgets, provenance, and review state.
  4. Private vault: reviewed Markdown is canonical; inbox candidates are not durable facts.
  5. Disposable projections: SQLite FTS, reports, and exports can be rebuilt from Markdown.

Repository ≠ installed executable ≠ private vault. Collapsing these locations breaks the privacy and release model.

A memory-bearing request

The following component flow shows responsibility, not measured latency. Its numbered outline is the canonical text fallback.

Python serviceretrieval + review rules

  1. The host decides when a task merits recall and submits a bounded local request.
  2. The transport binds the request to an explicit root and server-enforced tool profile.
  3. Policy checks capability, path, input size, context budget, and hard ceilings.
  4. Python queries a rebuildable index and revalidates results against canonical Markdown.
  5. The client receives context with provenance fields instead of an opaque generated answer.

Recall is not durable writing

The system deliberately separates a low-friction read path from a review-gated durable path.

Read path

Search the index, open the canonical Markdown source, enforce visibility and budget, then return provenance-bearing context.

Proposal path

Place a bounded candidate in a review queue. Scan it, resolve conflicts, record reviewer identity, then promote approved Markdown.

Durable values are pinned. Automation may prepare review material and consolidation candidates, but it does not silently overwrite durable memory.

Why Python remains authoritative

The current product is filesystem-heavy, headless, cross-platform, and already mature in Python. Rewriting the domain runtime in Node would duplicate recovery, policy, packaging, and security behavior before delivering a distinct capability.

Runtime responsibility boundary
Concern Python owns now A future Node plane may own
Canonical data Markdown identity, policy, reviews, writers, recovery Never canonical authority
Headless operation CLI, MCP, local API, hooks, maintenance, backup Not required for installation or operation
Visual experience Versioned language-neutral contracts TypeScript client, React dashboard, build tooling

A TypeScript/React dashboard can still add real value if it consumes generated contracts and remains removable. Reconsider the runtime split only with measured product evidence: contract parity, safer packaging, lower operating cost, and a rollback that preserves Markdown bytes, IDs, and review receipts.

Decision source: ADR 0254 — Python/Node runtime boundary.

Processes have an owner and an exit

In the current 2.1.0 source line, generated MCP servers self-expire and package-owned descendants run inside an independently reaped process group or tree.

Client launchesexplicit vault + server profile
Server bindsroot validation before tools
Requests runbounded frames, output, and time
Exit triggersEOF, idle lease, deadline, shutdown
Tree is reapedowned descendants terminate too
  • Idle leases are 120 / 600 / 1,800 seconds for minimal / balanced / active.
  • Git and maintenance children receive closed stdin, bounded output, and a deadline.
  • Windows uses a kill-on-close Job Object; POSIX uses an owned session/process group.
  • A client can reconnect on its next request after an idle exit.

These guarantees cover ai DeMemory and its owned children. The host application still owns unrelated browser, Node, Python, plugin, and agent processes.

Fail closed where authority changes

Invalid roots, out-of-range resource overrides, unauthorized MCP tools, stale scheduler receipts, secret-like durable content, and changed review fingerprints block the corresponding operation.

Generated indexes remain disposable. If retrieval infrastructure is absent or stale, rebuild it from Markdown; never reverse the authority direction. Hook injection can fail open with no recalled context, but it must not manufacture durable knowledge.
